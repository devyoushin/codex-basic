# Codex 고급 활용 패턴

## 1) “읽기”를 병렬화해서 속도 올리기

- 여러 파일/검색은 한 번에 모아서 실행(컨텍스트 수집 시간을 줄임)
- 단, 수정(`apply_patch`)은 충돌 방지를 위해 한 번에 하나씩

## 2) 작은 패치로 리스크 줄이기

- 패치를 1) 안전한 리네이밍/정리, 2) 로직 변경, 3) 테스트/문서 순으로 분리
- 실패 시 롤백이 쉬운 단위로 쪼개기

## 3) “가장 좁은 검증” 루틴

우선순위:
1. 변경 파일과 직접 관련된 단일 테스트/커맨드
2. 해당 패키지/모듈 테스트
3. 전체 테스트

## 4) 원인 중심 디버깅 템플릿

- 증상: 관측된 에러/로그/재현 절차
- 원인: 왜 그렇게 되는지(조건/경로)
- 해결: 최소 수정
- 방지: 테스트/가드/문서

`templates/debug-runbook.md` 사용.

## 5) 작업 흔적을 “재사용 가능한 자산”으로 남기기

- 같은 문제가 다시 나오면:
  - `rules/`에 규칙 추가
  - `templates/`에 템플릿 추가
  - `codexops/log.md`에 세션 로그 추가
