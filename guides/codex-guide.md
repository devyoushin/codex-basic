# Codex CLI 가이드 (레포 작업 기준)

## 1. Codex를 “레포 작업자”로 쓰는 핵심

Codex의 강점은 **코드/문서/설정 변경을 실제로 적용하고**, 가능한 경우 **명령으로 검증**까지 이어가는 흐름입니다.

표준 루프:

1) 탐색(검색/읽기) → 2) 가설(원인/해결) → 3) 최소 패치 → 4) 좁은 검증 → 5) 정리

## 2. 탐색: 빠른 컨텍스트 수집

권장 순서:
- `rg "<키워드>"`로 관련 파일 후보 찾기
- `sed -n '1,200p' <file>`로 필요한 구간만 읽기
- 필요하면 `git log`, `git blame`로 의도/히스토리 확인

## 3. 변경: 작은 패치, 명확한 의도

원칙:
- “요구사항을 만족하는 최소 변경”만 수행
- 이름/포맷/구조 변경은 요청이 있거나 필요할 때만
- 파일이 여러 개면, **원인/의존성 기준으로 묶어서** 단계적으로 변경

## 4. 검증: 가장 좁은 것부터

추천:
- 변경한 모듈/패키지의 단일 테스트 → 관련 테스트 묶음 → 전체 테스트(필요 시)
- 테스트가 없으면: 최소 실행/빌드/린트 중 가능한 것 1개라도 수행

## 5. 권한/승인(에스컬레이션) 감각

다음은 종종 승인(샌드박스 밖 실행)이 필요:
- 네트워크 접근(패키지 설치, 원격 push/pull 등)
- 시스템 전역 경로 변경

승인 요청 시:
- “왜 필요한지”를 1문장으로 설명
- 가능하면 재사용 가능한 prefix(예: `git push`)로 승인 범위를 좁게

## 6. 결과 전달(사용자에게)

최종 응답 체크:
- 무엇을 바꿨는지(파일 경로 기준)
- 어떻게 검증했는지(실행한 명령)
- 다음에 무엇을 하면 좋은지(옵션)
